# test_numbers.txt -- the registry of the numbered test cvars' numbers (docs/vr-port/TESTING.md, "Test numbers").
# Checked on every build (Misc/quakevr/check_test_numbers.py, run by the kit's build.sh): the build FAILS when two
# lines claim one number, two dispatch branches take one number, a dispatched number is missing here, a line here is
# dispatched by nothing, or a Debug menu command runs a number not here.
#
# Claiming a number: add its line here in the same commit as its dispatch branch (pick a number no line has; a block
# like 50-59 belongs to its file: a number inside it is that file's to give). Two workers claiming the same number
# then conflict in this file at the merge, and the build fails on whatever slips through.
#
#   dispatch <cvar> <file> <function> <variable> [within A-B|A+] [loose]
#       a function whose `if(<variable> == N)` / `if(<variable> >= A && <variable> <= B)` branches dispatch the cvar;
#       a branch calling another dispatch function hands it those numbers (its own branches are the numbers then);
#       `loose`: its own branches may share a number (a set-up branch, then the case's): only the registry's
#       claims, the coverage and the clashes with the cvar's other dispatchers are checked
#   <cvar> <N | A-B | A+> <file> <what it tests>
#       N* (A-B*): run by the dispatcher's fall-through (`if(req) { ... }` past its numbered branches), no branch of its own
